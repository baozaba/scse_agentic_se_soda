===== RUN 1 =====
1. **Process Input Data**: The system must receive and interpret input data indicating whether the path ahead, to the left, and to the right is blocked.  
2. **Determine Goal Direction**: The system must identify whether the goal is located ahead, to the left, or to the right of the robot.  
3. **Prioritize Goal Movement**: The robot must attempt to move toward the goal’s direction only if that path is unblocked.  
4. **Avoid Blocked Directions**: The system must never issue a movement command into a direction that is blocked.  
5. **Stop When No Safe Path Exists**: If all possible directions (ahead, left, right) are blocked, the robot must stop and remain stationary.  
6. **Handle Dynamic Environments**: The navigation logic must adapt to changing blocked paths and goal positions during operation.  
7. **Ensure Safety Over Efficiency**: The system must prioritize avoiding collisions (by respecting blocked directions) over reaching the goal.  
8. **Support Simulated Testing**: The navigation logic must be compatible with multiple simulated environments, including varying layouts and obstacles.  
9. **Provide Clear Movement Commands**: The system must output explicit movement instructions (e.g., "move forward," "turn left") based on the current state of blocked paths and goal location.  
10. **Maintain Continuous Decision-Making**: The robot must continuously reassess its movement options in real time as new input data becomes available.

===== RUN 2 =====
1. The system must receive input indicating whether the path ahead, to the left, and to the right is blocked.  
2. The system must receive input indicating the direction of the goal (ahead, left, or right).  
3. The navigation logic must prioritize movement toward the goal whenever it can be done safely.  
4. The system must prevent movement into any blocked direction.  
5. If no safe movement directions are available, the robot must stop.

===== RUN 3 =====
1. The system must receive input indicating whether the path in front, to the left, and to the right is blocked.  
2. The system must receive input indicating the direction of the goal (ahead, to the left, or to the right).  
3. The system must prioritize movement toward the goal whenever it can be done safely.  
4. The system must not allow movement into any blocked direction.  
5. If no safe movement direction is available, the system must stop the robot.  
6. The system must be compatible with multiple simulated environments for testing.
